# site/

The static site is generated by `oml build-site` into `site/_build/` (ignored
by git) and deployed to GitHub Pages by `.github/workflows/pages.yml` on
every push to `main`.

* The base URI is the single value `base_uri` in `oml.config.json`. Change
  it there and rebuild; every record `uri` must match, so `oml validate`
  will tell you which records to update (a scripted rewrite is a one-liner
  over `records/`).
* `/m/<id>` is served from `m/<id>.html`; `/m/<id>.json` is the record.
  GitHub Pages resolves extensionless paths to `.html`, so no redirects are
  needed and the URIs survive a move to any host that does the same (or one
  with content negotiation).
* Anything in `site/static/` is copied over the build output verbatim
  (`CNAME` goes here once the domain is decided).
* The site includes `oml.case.json`, `oml.jsonl`, `oml.csv` and
  `records.json` at the root so consumers can fetch the whole library from
  the base URI.
